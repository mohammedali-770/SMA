# Visual review without a WhatsApp OTP

## The fixture route

`apps/mobile/src/app/dev-preview.tsx` renders the **real production components**
against deterministic mock data.

```
/dev-preview            menu product cards
/dev-preview?c=cart     cart lines
/dev-preview?c=riyal    the Riyal symbol across the type scale
```

It is safe in production by four independent mechanisms:

1. `if (!__DEV__) return <Redirect href="/" />` — a release build renders
   nothing and bounces to home.
2. Nothing links to it; it is reachable only by typing the path.
3. Every handler is a no-op `() => {}`. There is no code path from this file to
   an API, to Supabase, to order creation or to payment.
4. All data is local `MOCK_*` constants. No fetch, no store, no network.

**Limitation.** These are component-level fixtures. Whole-screen fixtures for
ProductDetail, Checkout and Payment need the catalog and cart React contexts
exported from `src/store` so a mock provider can supply them. That is the next
step for this route and is deliberately not bundled into a surface migration.

## Running a visual pass

```bash
npm --prefix apps/mobile run web      # or: npx expo start --web --port 8099
```

Then open `http://localhost:8099/login` and `http://localhost:8099/dev-preview`.

## ⚠ `expo start --web` rewrites a tracked file

Starting the Expo web server **modifies `apps/mobile/tsconfig.json`** — it
rewrites the `include` array and strips `.expo/types/**/*.ts` and
`expo-env.d.ts`. The edit is generated by the Expo CLI, not authored, and it
must never be committed: dropping those entries removes the generated router
types from typechecking.

**Before committing after any visual pass:**

```bash
git diff --stat apps/mobile/tsconfig.json     # expect: no output
git checkout -- apps/mobile/tsconfig.json     # if it is dirty, revert it
```

`scripts/check-design-system-hygiene.mjs` fails the build if the file drifts
from its committed contents, so CI catches it even if the check above is
forgotten.
