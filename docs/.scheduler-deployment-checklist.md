# Scheduler deployment checklist

- [ ] `account_deletion_project_url` exists once in Vault.
- [ ] `account_deletion_process_secret` exists once in Vault.
- [ ] `verify_account_deletion_process_secret(text)` is live and service-role-only.
- [ ] `account-delete-scheduler` (the gateway the cron job actually calls) and `account-delete-process` are both deployed from the matching merged source.
- [ ] Queue is empty before authorized no-op verification.
- [ ] Scheduler migration is applied (the live version is recorded in `docs/MIGRATIONS.md`). Do **not** "align" or repair migration history: live versions are apply-time stamps by design and `supabase migration repair` is forbidden against Production (CLAUDE.md §8).
- [ ] Cron job is unique, active, and runs every minute.
- [ ] At least two scheduled invocations return HTTP 200 (read the status from `net._http_response`; `cron.job_run_details` only shows that the SQL ran).
- [ ] Queue and Auth-user counts remain unchanged during no-op verification (`public.account_deletion_requests` grouped by status, and the `auth.users` count; take both before and after).

_Added 2026-11-26: this checklist was written for the original rollout (the scheduler migrations are dated 2026-07-16) and carries no ticks. The job is live (`docs/account-deletion-scheduler.md`, `docs/BACKUP_RECOVERY.md`), so read it as the verification list for a rebuild of the scheduler, not as pending work._
